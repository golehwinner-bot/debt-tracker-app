# Журнал боргів — деплой на Vercel із синхронізацією між пристроями

Дані зберігаються в Redis (через Marketplace-інтеграцію **Upstash for Redis** — власний продукт
"Vercel KV" закрили у 2024, зараз під капотом саме Upstash, але механіка та ж).

## Крок 1. Встановити залежності
```
cd debt-tracker-app
npm install
```

## Крок 2. Перший деплой (без бази — це нормально)
```
npx vercel --prod
```
Йдіть за підказками CLI (логін, назва проєкту — все за замовчуванням підходить).

## Крок 3. Підключити Redis через Marketplace

**Варіант А — через CLI (найшвидше):**
```
npx vercel install upstash
```
Оберіть проєкт → створіть нову базу (або підключіть існуючу) → CLI сам додасть змінні середовища.

**Варіант Б — через дашборд:**
1. vercel.com → відкрийте проєкт → вкладка **Storage**
2. **Browse Marketplace** → знайдіть **Upstash** → **Add Integration**
3. Створіть Redis-базу, підключіть до вашого проєкту
4. Vercel сам додасть змінні `KV_REST_API_URL` і `KV_REST_API_TOKEN` до проєкту

## Крок 4. Передеплоїти, щоб підхопились нові змінні
```
npx vercel --prod
```
(Env-змінні застосовуються тільки з наступним деплоєм.)

Готово. Відкрийте посилання на телефоні й на комп'ютері — дані спільні.

## Локальна розробка з підключеною базою (необов'язково)
```
npx vercel env pull .env.development.local
npm run dev
```

## Індикатор у застосунку
Зверху праворуч — крапка:
- 🟢 **синхронізовано** — дані записані в базу, видно з будь-якого пристрою
- 🔴 **офлайн (локально)** — API недоступне (наприклад, база ще не підключена), дані тимчасово тільки в браузері цього пристрою

## Про доступ
Це не має пароля/авторизації — будь-хто з посиланням зможе бачити й редагувати дані.
Якщо небажано — додайте пароль через Vercel Password Protection
(Project → Settings → Deployment Protection).
